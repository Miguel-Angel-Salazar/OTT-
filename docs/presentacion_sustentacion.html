01 · Contexto y Necesidad

Visibilidad Cultural y Autonomía de Infraestructura

El proyecto responde simultáneamente a una brecha en la distribución de cine regional y a los retos operativos de mantener una plataforma multimedia reproducible.

Dimensión de Producto

Curaduría de Cine Colombiano e Independiente

  • Problema: Los catálogos comerciales masivos relegan el cine independiente y las producciones latinoamericanas frente a algoritmos genéricos.
  • Espectadores / Suscriptores: Requieren un catálogo organizado por región (LATAM, EUROPA, USA), reproducción continua con memoria del segundo exacto de visualización, lista personalizada y calificaciones.
  • Operadores y Auditores: Requieren endpoints de diagnóstico en vivo (/api/health) y contratos REST documentados en OpenAPI (/apidocs/).
Dimensión de Ingeniería

Eliminación de Dependencias Externas y Monolito

  • Acoplamiento inicial: La primera iteración dependía de una base de datos externa en la nube (Supabase), impidiendo despliegues autónomos y reproducibles.
  • Saturación por archivos multimedia: Servir archivos de video MP4 y renderizar plantillas HTML desde el mismo proceso Python bloqueaba los hilos del servidor.
  • Riesgo de regresión: La ausencia de un pipeline de integración continua permitía que cambios en consultas SQL o rutas afectaran la rama principal sin detección previa.

02 · Solución Implementada

Propuesta de Valor, Funcionalidades y Alcance

Una plataforma de video bajo demanda 100% autónoma que inicializa su propio esquema relacional, activos multimedia y reglas de negocio en cualquier entorno.

Experiencia de Usuario

Capacidades en Producción

  • Autenticación Criptográfica: Registro, login y cambio de clave con hashing bcrypt y sesiones firmadas.
  • Catálogo Regional (20 Obras): Selección dedicada de Cine Colombiano (Monos, El olvido que seremos, La vendedora de rosas, Pájaros de verano, El páramo).
  • Reproductor con Estado: Persistencia automática del segundo de reproducción en base de datos (watch_history).
  • Interacción: Gestión de Mi Lista (favoritos), sistema de Likes/Dislikes, buscador instantáneo y cambio de plan de suscripción.
Diferenciador Técnico

Portabilidad sin Servicios Externos

  • Base de Datos Propia: Migración completa a PostgreSQL 16 Alpine con 6 tablas relacionales e integridad referencial (ON DELETE CASCADE).
  • Sembrado Automático: El script init.sql aprovisiona estructura, usuarios de prueba y catálogo sin intervención manual.
  • Separación de Tráfico: Nginx entrega los videos MP4 directamente desde disco con caché, liberando al backend Flask.
Transparencia Técnica

Límites del Alcance Actual

  • Entrega Multimedia: Streaming HTTP progresivo de archivos MP4 locales (no incluye transcodificación adaptativa HLS multi-bitrate).
  • Reconciliación en Clúster: Estado declarativo versionado en Git (k8s/) aplicado sobre Minikube mediante kubectl apply, sin requerir operadores externos como Argo CD o Jenkins.

03 · Decisiones de Ingeniería

Stack Tecnológico y Justificación DevOps

Capa / Práctica Tecnología y Versión Por qué se eligió en esta arquitectura Compensación (Trade-off) asumida
Proxy Inverso & Estáticos Nginx 1.25-alpine Entrega directamente /static/* (videos MP4 y pósters) con caché de 30 días y enruta peticiones dinámicas a Flask. Introduce un contenedor adicional que requiere sincronizar la variable BACKEND_URL.
Backend & API REST Python 3.11 · Flask 3.1.1 · Flasgger Estructura modular en Blueprints MVC, renderizado SSR con Jinja2 y especificación interactiva OpenAPI en /apidocs/. Requiere sondas de salud activas (/api/health) para supervisar la conexión con PostgreSQL.
Persistencia Relacional PostgreSQL 16-alpine · psycopg2 Garantiza integridad referencial y restricciones UNIQUE en favoritos, calificaciones e historial de reproducción. Exige desplegarse como StatefulSet con un PersistentVolumeClaim para no perder datos al reiniciar pods.
Integración Continua (CI) GitHub Actions · Pytest · Playwright Levanta un contenedor PostgreSQL real por cada commit/PR, ejecuta las pruebas y valida la sintaxis de los manifiestos K8s. Mayor tiempo de ejecución del workflow (~45 s) frente a pruebas simuladas en memoria, a cambio de fidelidad real.
Orquestación Local Kubernetes (Minikube v1.39) Provee aislamiento por Namespace, inyección de Secret/ConfigMap, balanceo interno ClusterIP y Self-Healing. Empaquetar los 20 videos MP4 en la imagen de Frontend incrementa su tamaño (~380 MB) para garantizar ejecución 100% offline.

04 · Topología y Comunicación

Arquitectura Desacoplada en Tres Capas

El tráfico externo ingresa únicamente a través del proxy inverso Nginx; el servidor de aplicaciones y la base de datos permanecen aislados dentro de la red interna del clúster.

Capa 01 · Perímetro Web

Frontend & Reverse Proxy

ott-frontend · nginx:1.25-alpine

  • Expuesto mediante Service NodePort (80:30080).
  • Regla location /static/: Sirve videos MP4, pósters y CSS desde disco con Cache-Control: public, max-age=30d.
  • Regla location /: Redirige tráfico dinámico mediante proxy_pass http://ott-backend:5000.

Capa 02 · Lógica de Negocio

Backend MVC & OpenAPI

ott-backend · python:3.11-slim

  • Aislado mediante Service ClusterIP interno (puerto 5000).
  • 6 Blueprints: auth, home, movie, favorite, profile y api.
  • Ejecuta bajo usuario sin privilegios (appuser) y expone /api/health y /apidocs/.

Capa 03 · Persistencia

Base de Datos Relacional

ott-db-0 · postgres:16-alpine

  • Desplegado como StatefulSet con Service ClusterIP (puerto 5432).
  • Almacenamiento persistente montado en postgres-pvc (1 GiB).
  • Inicialización automática mediante el ConfigMap ott-db-init (init.sql).

06 · Aseguramiento de Calidad Automatizado

Pipeline CI/CD en GitHub Actions y Control de Fallos

Arquitectura del Pipeline

Dos Etapas con Compuerta de Calidad

  • Etapa 1 · Pruebas con PostgreSQL Real: Aprovisiona un contenedor de servicio postgres:16-alpine, carga database/init.sql y ejecuta las suites unitarias y de flujo de comunicación.
  • Política de Control de Fallos: La Etapa 2 declara needs: unit-and-integration-tests junto con if: success(). Cualquier fallo en una prueba detiene el pipeline e impide construir o promover imágenes.
  • Etapa 2 · Build, Validación K8s y Trazabilidad: Valida la sintaxis de todos los YAML en k8s/, verifica coherencia de versión (v1.0.0), construye las imágenes con tag SHA y genera el reporte en el Job Summary.

Ejecución de la Suite Automatizada

07 · Construcción y Distribución de Artefactos

Buenas Prácticas en Dockerfiles y Docker Hub

Ingeniería de Contenedores

Optimización y Seguridad en Imágenes

  • Aprovechamiento de Caché de Capas: En backend/Dockerfile se copia e instala requirements.txt antes de copiar el código de la aplicación, evitando reinstalar dependencias ante cambios en controladores.
  • Ejecución sin Privilegios (Non-Root): Se crea el usuario del sistema appuser y se transfiere la propiedad de /app para ejecutar Flask bajo USER appuser.
  • Higiene del Contexto: Archivos .env, entornos virtuales y cachés excluidos vía .dockerignore.
  • Etiquetado Trazable: Imágenes publicadas en Docker Hub bajo versión semántica (v1.0.0), hash de commit (sha-a8b8492) y latest.

09 · Gestión de Configuración y Seguridad

Protección de Credenciales y Aislamiento por Entorno

Defensa en Profundidad

Gestión Segura de Variables y Red

  • Desacople Código / Configuración: El backend lee DATABASE_URL y SECRET_KEY exclusivamente desde variables de entorno; .env está excluido del control de versiones.
  • Separación ConfigMap vs Secret: Parámetros no sensibles residen en ott-config, mientras que credenciales de base de datos y llave de sesión se almacenan en Secret ott-secrets codificadas en Base64 e inyectadas vía secretKeyRef.
  • Cifrado de Contraseñas: Las claves de usuario se almacenan en PostgreSQL como hashes bcrypt con factor de costo 12 ($2b$12$...).
  • Superficie de Red Mínima: Ni PostgreSQL ni Flask poseen puertos públicos hacia el host; solo Nginx recibe conexiones externas.
Auditoría en Vivo

Verificación sin Exposición de Datos Sensibles

# Comprobar que .env está protegido por .gitignore git check-ignore -v .env # Listar objetos de configuración en el namespace kubectl get configmap,secret -n ott-platform # Inspeccionar estructura del Secret sin revelar valores en claro kubectl describe secret ott-secrets -n ott-platform

10 · Operación y Diagnóstico

Observabilidad, Sondas de Salud y Self-Healing

Monitoreo y Recuperación

Comportamiento ante Fallos en el Clúster

  • Healthcheck Transaccional (/api/health): Ejecuta una consulta real SELECT 1 hacia PostgreSQL. Si la base de datos deja de responder, el endpoint retorna HTTP 500.
  • Readiness & Liveness Probes: Kubernetes retira automáticamente del balanceador cualquier pod que no supere la readinessProbe y reinicia el contenedor si falla la livenessProbe.
  • Autorrecuperación (Self-Healing): Ante la caída o eliminación abrupta de un pod, el controlador del Deployment instancia un reemplazo inmediato sin pérdida de datos en el StatefulSet de PostgreSQL.
Diagnóstico en Vivo

Inspección de Logs y Simulación de Incidente
